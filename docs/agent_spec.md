# 智能体操作规范

## 1. Docker 容器文件修改规范

### 问题
使用 `docker cp` 修改运行中容器的文件是**临时操作**，容器重启后修改会丢失，恢复为镜像中的原始版本。

### 规则
**禁止通过 `docker cp` 修改容器内文件作为最终交付手段。**

正确流程：
```
修改本地源码 → 重新构建镜像 → 停止旧容器 → 启动新容器
```

### 例外
`docker cp` 仅可用于**临时调试**（验证修改是否生效），调试完成后必须重新构建镜像。

---

## 2. 黑盒镜像构建规范

### 构建前检查清单
- [ ] 确认所有源码文件已更新到本地最新版本
- [ ] 确认 `stream_test.html` 等前端文件已同步
- [ ] 确认 `start_merged.sh` 启动脚本已同步
- [ ] 确认 Dockerfile 中的 COPY 路径与构建上下文匹配

### 构建命令
```bash
cd /opt/argosasr && docker build -f Dockerfile.blackbox -t argosasr-streaming-delivery:v5.7 .
```

### 构建后验证
```bash
# 验证前端版本
docker exec <容器名> grep "Argos ASR" /opt/streaming-asr/src/stream_test.html

# 验证源码已编译
docker exec <容器名> ls /opt/streaming-asr/src/*.pyc

# 验证无 .py 残留
docker exec <容器名> ls /opt/streaming-asr/src/*.py 2>&1 | grep -v "No such"
```

## 3. 部署更新流程

### 完整更新步骤
```
1. 修改本地源码文件
2. 上传源码到服务器构建上下文（/opt/argosasr/src/）
3. 重新构建镜像（docker build）
4. 停止并删除旧容器（docker stop + docker rm）
5. 用新镜像启动容器（docker run）
6. 健康检查验证（curl /health）
7. 验证容器内文件版本
```

### 禁止的快捷操作
- 禁止 `docker cp` 修改后直接重启（修改会丢失）
- 禁止只上传文件不重建镜像
- 禁止跳过构建后验证步骤

---

## 4. 镜像版本管理

- 每次代码变更后必须重新构建镜像
- 镜像标签格式：`argosasr-streaming-delivery:v{版本号}`
- 同时打 `:latest` 标签指向最新版本
- 部署手册中的镜像版本必须与构建版本一致

## 6. 调试方法论规范

### 6.1 方向性验证先于参数调优

**规则：** 调试阈值/超时类参数前，先做对照实验确认方案方向可行，禁止在错误方向上反复调参。

案例（回声打断问题）：在能量阈值上多轮调参（0.02→0.03→0.1→0.4）无效后才认识到——回声能量随外放音量任意增大（实测 0.021~0.11+，无上限），静态能量阈值方案本质不可行，正确方向是时间隔离（两步式 dialplan）。

**正确流程：**
```
先做对照实验验证方向（如：不同音量下回声能量曲线）
→ 方向可行才进入参数调优
→ 方向不可行立即换方案，不在参数上耗时间
```

### 6.2 调试密集参数必须支持热调

**规则：** 调试期间需频繁调整的参数（阈值、超时等）应设计为运行时热调接口，避免每次改动走"改代码→上传→重编译→重启"完整链路。

- 热调接口模式：管理路由（如 `/admin/vad`）+ 鉴权 token + GET/POST，参数立即生效
- 参数取值范围、默认值必须在接口代码与文档中同时明确
- 环境变量可覆盖初始值，便于不同部署环境定制

### 6.3 结论必须实测数据支撑

**规则：** 排查结论须基于实测数据（能量序列、音频回放等多源交叉验证），禁止仅凭日志表象下判断。

- 日志采样/截断可能误导排查（案例：网关日志只打印前 3 帧音频，被误判为"断流"，实际音频完整到达）
- 判断故障前先用独立数据源验证（如 utter 落盘音频文件回放）

## 7. 可观测性规范

### 7.1 日志采样必须留痕

**规则：** 日志采样/截断（如只打印前 N 帧）必须在代码注释或文档中说明，防止后续排查误判为故障。

### 7.2 关键决策指标内建于日志

**规则：** 状态机关键决策点必须输出触发源与指标值，为事后排查提供抓手。

- 示例：`speech_start (VAD) rms=0.0452` vs `speech_start (ASR) text=...` —— 括号标明触发源，可直接区分能量触发与识别兜底触发

### 7.3 多端日志统一基准

**规则：** 多组件日志需统一时区或明确标注换算关系；会话需有统一关联 ID 便于跨端串联。

- 已知约定：`docker logs -t` 为 UTC，比 FreeSWITCH/UniMRCP 日志（CST）慢 8 小时，对照时 +8 小时
- 会话 ID（如 `mrcp-xxx`）应贯穿三端日志（FS → 插件 → 网关）

## 8. 资源生命周期与竞态防护规范

### 8.1 代次/令牌机制防竞态

**规则：** 延迟关闭 + 连接复用的组合必然产生竞态；新一轮开始必须递增代次（generation）并作废旧连接，旧连接的迟到结果按代次丢弃。

案例：end 后 3 秒延迟关闭期间新 start 复用旧 Runtime WS，旧 final 结果污染新会话 → 用 `ws_generation` 轮次机制修复。

### 8.2 状态残留入口校验

**规则：** 跨会话/跨轮次的状态字段，在新一轮入口处必须重置并校验，防止上一轮残留污染本轮。

案例：全静音音频却识别出提示音全文（Runtime 状态残留）→ `max_rms` 入口归零 + 全静音校验丢弃残留文本。

### 8.3 事件循环内禁止阻塞操作

**规则：** 异步事件循环/回调路径禁止 sleep 等阻塞调用；耗时的清理/关闭操作移入后台线程。

案例：`_close_runtime_ws` 中 `sleep(1)` 阻塞内部 WS 事件循环 → 移入 `threading.Thread(daemon=True)` 后台关闭。

## 9. 文档同步与命令示例规范

### 9.1 代码变更必须同步文档

**规则：** 代码行为变更（dialplan 示例、参数表、默认值、接口）必须在同一变更内更新文档，禁止代码先行文档滞后。

案例：dialplan 改为两步式后，deployment.md 中的单步式示例未同步，会直接误导客户部署。

### 9.2 命令示例适配用户实际环境

**规则：** 文档命令示例必须覆盖目标用户实际环境，必要时提供双版本。

- Windows PowerShell 下 `curl` 是 Invoke-WebRequest 别名，须用 `curl.exe`，JSON 引号需转义：`-d '{\"threshold\": 0.04}'`
- 文档中 bash 与 PowerShell 命令示例并存（见 docs/operations.md 第 3.4 节）

### 9.3 变更后验证闭环

**规则：** 部署/热调后必须验证新状态实际生效，而非仅确认服务存活。

- 健康检查（`/health`）+ 参数生效确认（GET 管理接口核对实际值）双验证
